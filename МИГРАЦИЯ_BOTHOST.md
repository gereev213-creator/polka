# Переезд ПОЛКИ на BOTHOST

Проверено по документации: https://bothost.ru/docs/ (веб-приложения, хранение БД,
кастомный Dockerfile, Mini App).

## Что уже готово в коде

| Требование BOTHOST | Состояние |
|---|---|
| Слушать `0.0.0.0` | ✅ `TCPSite(runner, '0.0.0.0', WEBAPP_PORT)` |
| Читать порт из `PORT` | ✅ `WEBAPP_PORT = env PORT` |
| База в `/app/data` | ✅ путь подстраивается сам, если папка существует |
| Dockerfile | ✅ есть, `WORKDIR /app` |
| HTTPS-домен | ✅ платформа даёт поддомен `*.bothost.tech` |

## Шаг 1. Регистрация и бот

1. Зарегистрироваться на bothost.ru, пополнить на тариф **«Базовый» 99 ₽**.
   Бесплатный (256 МБ) не подойдёт: приложению нужно ~300 МБ под базу и кэш.
2. Создать бота: **«Из Git-репозитория»** → указать репозиторий `amvera-upload` (ветка master).
3. Платформа сама найдёт `Dockerfile` и соберёт образ.

## Шаг 2. Переменные окружения

Обязательные:

```
BOT_TOKEN                 — токен из @BotFather
ADMIN_READ_TOKEN          — токен для /api/diag и /api/admin/sql
INGEST_TOKEN              — токен сборщика (если он шлёт находки сюда)
DB_PATH                   =  /app/data/polka.db
```

Для оплаты:

```
PAW_MNT_ID                — номер бизнес-счёта PayAnyWay
PAW_INTEGRITY_CODE        — код проверки целостности
PAW_TEST_MODE             =  0
```

Необязательные: `PAW_CURRENCY` (RUB или 643), `AI_API_KEY` (если используется).

## Шаг 3. Домен

1. В настройках бота включить **«Использовать домен»**.
2. Выбрать автоматический поддомен (например `polka.bothost.tech`) или свой.
3. **Внутренний порт** — тот же, что в `PORT` (обычно платформа подставляет сама).
4. Сделать **повторный деплой** после смены домена — без этого маршрутизация не применится.

Проверка: `https://ваш-домен/health` должен вернуть `{"status":"ok"}`.

## Шаг 4. База данных

База сейчас **470 МБ**. Варианты:

**А. Перенести как есть.** Скачать `polka.db` с Amvera, загрузить в `/app/data`
через файловый менеджер BOTHOST. Медленно (10–30 минут), зато сохраняется история.

**Б. Почистить и перенести.** Удалить старые находки — база уменьшится в разы,
загрузка станет быстрой. Чистка полезна и без переезда.

**В. Начать с пустой.** Бот создаст базу сам, сборщик наполнит заново.
**История и 44 тысячи находок потеряются.** Не рекомендую.

После загрузки обязательно **удалить файл базы из репозитория**, если он там окажется:
BOTHOST синхронизирует код с git, а `/app/data` исключена из синхронизации.

## Шаг 5. Переключение

Порядок важен, иначе Telegram будет ругаться на два одновременных `getUpdates`:

1. **Остановить Amvera** (или отключить бота там).
2. Убедиться, что новый бот запустился: в логах BOTHOST строка о старте.
3. Проверить `https://ваш-домен/health`.
4. В @BotFather: **Bot Settings → Menu Button → Edit menu button URL** — указать новый адрес.
5. Проверить оплату: тарифы → «Оплатить» → форма PayAnyWay.

## Шаг 6. Сборщик находок

Сборщик живёт отдельно (UserLAnd/телефон) и шлёт находки на `INGEST_TOKEN`.
В его `config.json` нужно поменять адрес сервера на новый домен:

```json
{ "server": "https://ваш-домен", "ingest_token": "..." }
```

Если сборщик запустить на BOTHOST — он съест память (Playwright не установлен,
но парсер тяжёлый). Лучше оставить отдельно.

## Что проверить после переезда

- [ ] бот отвечает на `/start`
- [ ] Mini App открывается из меню бота
- [ ] лента находок грузится
- [ ] создание объявления работает
- [ ] тарифы показывают 49 / 149 / 349 ₽
- [ ] оплата открывает форму PayAnyWay
- [ ] после оплаты приходит уведомление и «Плюс» включается
- [ ] `/health` возвращает `payment.paw_enabled: true`

## Если что-то не так

| Симптом | Причина |
|---|---|
| 502 / 504 | приложение не слушает `PORT` или порт не совпал с настройкой |
| 404 на `/` | нормально, если приложение отдаёт только API; проверить `/health` |
| база пропала после рестарта | писали не в `/app/data` — проверить `DB_PATH` |
| `Conflict: terminated by other getUpdates` | старый сервер ещё работает, выключить Amvera |
| Mini App не открывается | домен не включён или деплой не перезапущен после смены домена |
